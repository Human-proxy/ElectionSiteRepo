# Election Quiz Feature
# Author: Aydin Maleki

This document explains how the interactive Election Quiz is built across the backend (Spring Boot + Java) and the frontend (Vue 3 + Vuetify). 

---

## 1. Overview

The Election Quiz transforms raw election data into an engaging user experience by providing:

- Dynamic Questions  
  Dropdowns (parties, regions, data types) update automatically when a year is selected.

- Smart Data Retrieval  
  Handles differences between election data for 2017, 2021, and 2023.

- Creative Visualizations  
  Including animated counters, progress circles, and parliament (hemicycle) charts.

The frontend remains clean and simple while the backend handles all complex mapping, filtering, and history logic.

## 3. Backend Explained

### 3.1 Dynamic Question Configuration

File: QuizService.java

Questions and dropdown options are generated by the backend.  
The frontend does not store party lists, region lists, or any year-specific logic.

**Why:**
- Party names can change between years (e.g., GroenLinks → GroenLinks-PvdA)
- Municipalities merge or split
- Party IDs change each election
- Ensures frontend remains simple and lightweight

---

### 3.2 Region Fallback Strategy

File: MunicipalityService.java

Election years differ in completeness. To ensure the “Region” dropdown is never empty, a fallback system is used:

| Attempt | Source | Best For |
|--------|--------|----------|
| Attempt 1 | MunicipalityResult | 2023 |
| Attempt 2 | Constituency relationships | 2021 |
| Attempt 3 | Master municipality table | 2017 |

This guarantees that the quiz always can show valid regions.

---

### 3.3 Smart Party Matching and Normalization

File: QuizService.java → fuzzyMatch()

Because party IDs differ per year, the system resolves mismatches by:

- Normalizing party names (remove dots, casing differences)
- Checking known mergers (e.g., PvdA + GroenLinks → GroenLinks-PvdA)
- Mapping historical party names to modern ones
- Matching by cleaned name instead of ID

This avoids errors when a user selects a party from one year but asks for data from another.

## 4. API Reference

Endpoints are public (allowed in SecurityConfig / JWT filter).

---

### 4.1 GET /api/quiz/questions

Fetches all quiz questions.  
If a year is included, the backend filters party and region options accordingly.

Example response (simplified):

[
  {
    "id": "q1",
    "type": "SELECT",
    "text": "In welk jaar wilt u de quiz doen?",
    "options": [{ "value": "2023", "label": "2023" }]
  },
  {
    "id": "q2",
    "type": "SEARCHABLE_SELECT",
    "options": [{ "value": 29, "label": "VVD" }]
  }
]

---

### 4.2 POST /api/quiz/result

Computes the final data point requested by the user.

Payload example:

{
  "year": "2023",
  "partyId": 29,
  "region": "Amsterdam",
  "dataType": "VOTES"
}

Possible dataTypes:
- SEATS
- VOTES
- PERCENTAGE

Response example:

{
  "partyName": "VVD",
  "regionName": "Amsterdam",
  "metricLabel": "Aantal Stemmen",
  "formattedValue": "21.964",
  "narrative": "In 2023 kreeg VVD in totaal 21.964 stemmen in Amsterdam."
}

## 6. Frontend Visualizations

### 6.1 SEATS → Parliament Hemicycle Chart

- Implemented using Chart.js
- Displayed as a semi-circle
- Shows party seats vs total 150 seats
- Matches parliament visual conventions

---

### 6.2 PERCENTAGE → Animated Circular Progress

- Implemented with Vuetify’s `v-progress-circular`
- Starts at 0% and animates to real value
- Large text value displayed in the center

---

### 6.3 VOTES → Ticket-Style Count-Up Animation

- Custom CSS card
- Smooth number animation (0 → final value)
- Gives dynamic “live stats” visual effect

## 7. Why These Choices

| Part | Decision | Reason |
|------|----------|--------|
| Municipality selector | Searchable select (autocomplete) | 342+ municipalities → normal dropdown is too big |
| Party matching | Name-based normalization | Party IDs change across years |
| Backend-driven questions | Full config from backend | Keeps frontend simple + avoids historical logic |
| Visual design | Glassmorphism | Matches global gradient (#3B82F6 → #8B5CF6) |
| Fallback handling | Graceful 404 messages | Prevents crashes when data is missing |

## 8. Summary

The Election Quiz is designed to be:

- Flexible across years  
- Robust against inconsistent data  
- Fully backend-driven  
- Visually engaging  
- Easy to extend  

The architecture ensures that the quiz remains reliable, expressive, and user-friendly even as election data evolves.
